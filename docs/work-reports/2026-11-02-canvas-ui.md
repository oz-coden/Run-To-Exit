## Initial checkpoint

Transport, status, instruction forms, immutable plan inspection, paged/scrollable event logs, help and stage information now use public Canvas UI factories. The map uses one layout-owned world region. The integer-step world model and stage data are unchanged.

Existing SDK supports move/clear, native editing, focus/reveal, nested scrolling and pointer ownership. No second UI framework is introduced. Command rows survive simulation updates; event history is paged at 80 entries to bound presentation nodes while retaining access to every event.

Text fields are used for validated integers: CanvasNumberInput intentionally clamps/snaps values, which would hide an out-of-range command entry. Validation rejects invalid/blank/composing drafts before creating commands.

First local checks: npm ci, TypeScript, all 35 world tests and production build passed. Browser checks and UI regression conversion are pending. Standard Playwright Chromium download returned invalid/truncated archives; a separate Chromium 153 runtime is being prepared. CI retains standard Playwright Chromium.

## Accessibility release dependency

Published 0.1.2 mirrors interactive controls but omits CanvasLabel text. A complete Canvas screen would therefore lose descriptions/status for assistive technology. Engine-owned text semantics must be tested from candidate tarballs before considering deployment. Native IME automation does not certify physical Japanese IME/mobile keyboard or screen-reader operation.

## Second checkpoint

- Both draft PRs are created: [Run To Exit #7](https://github.com/oz-coden/Run-To-Exit/pull/7), [Simpludify #11](https://github.com/oz-coden/Simpludify/pull/11).
- Scene recreation now creates fresh UI/state/Board ownership. Command edits queue focus until the next resolved layout on published 0.1.2. The candidate engine fixes this existing focus contract without adding a public method.
- Transparent world-slot ancestors avoid painting a UI background over the map. HTML now contains only metadata, an empty mount and the module entry. CSS only sizes that mount.
- Existing world model tests remain unchanged (35 pass). Initial real Canvas editor solution/clear test passed in Canvas2D at desktop width.
- Playback tests use a controlled browser clock so the continuous software renderer does not consume the test runner between individual input actions. Actual pointer/touch hits and native keyboard/input events remain in use; no game state is injected to solve the stage.
- `npm run test:sdk-candidate -- /absolute/core.tgz /absolute/web.tgz [Playwright arguments]` copies the current game to an isolated temporary directory, runs npm ci, installs both candidate archives there, regenerates its lockfile, and runs check/world/build/E2E with required label-semantic assertions. Source dependency manifests remain published 0.1.2.
- Automatic live-region announcements and physical screen-reader/IME/mobile-keyboard validation are not claimed. Drag reordering is not added: explicit up/down/delete controls work with keyboard and touch while preserving scroll gesture ownership.

## Focus, input and scale checkpoint

- Conflict log messages do not carry a direct command number in the unchanged model. The UI resolves the appropriate fixed-plan command from the recorded Conflict metadata; it never rewrites the world/log model.
- Command rows now retain identity on append as well as simulation ticks. Only deletion, reorder, person/plan replacement rebuild the rows. A newly appended row enables the former last row's down action.
- Long-form input restores Add focus after insertion/validation; published 0.1.2 requires explicitly releasing and restoring a logically unchanged focus after geometry changes. The candidate SDK corrects repeat focus/reveal.
- Map keyboard navigation now uses Scene-owned Action bindings. Aside from locating the mount element, game code has no document queries, element creation, DOM event listeners or native keyboard/input management.
- Found a published SDK disposal bug when a hovered/focused control invalidates the UI while disposal is releasing routing ownership. Candidate Core ignores invalidation after disposal; game Scene deactivation also releases logical focus before replacement.
- Browser clock control reduced the representative Canvas2D editor solution test from an earlier timeout to about 14 seconds on the local software renderer. The initial timed-out tests are not counted as successful runs.
- A first complete desktop Canvas2D pass attempt finished 7/10, exposing log selection, focus-test synchronization and repeat-Add visibility issues. After correction a second finished 9/10; the remaining disposal issue is under final verification. All earlier failures remain part of the evidence.
- CI separates desktop/320/390 and WebGL/Canvas2D into six jobs, with one foreground worker per job. Stress checks retain a bounded 180-second budget. Standard Playwright Chromium remains the CI runtime.

## Release continuation

Simpludify v0.1.3 publication is now authorized after validation. The earlier publication block is a checkpoint history, not a requirement for another approval. After registry verification the game will replace its 0.1.2 dependency/lockfile, enforce candidate semantics in normal CI, merge and verify Pages.

The candidate `inputMode: numeric` hint keeps raw text validation while requesting a numeric soft keyboard. Public 0.1.2 ignores that hint; the candidate validation checks its native attribute. Long-log stress setup now invokes the public Step control repeatedly to generate more than 80 real log entries without spending the test budget on idle rendering; history filtering, page switching and command deletion remain actual pointer/touch operations.

## 320px correction

Standard Chromium CI exposed a real compact-layout failure: the three verbose command-action buttons retained `shrink: 0`, so Delete was painted beyond the right edge. The action buttons now shrink and wrap within their row. The actual 320px touch deletion stress test passes after the correction (50 commands, limit validation, deletion and >80 log entries/page navigation). Test pointer helpers also reject a control whose center is clipped instead of silently tapping outside the target.

Long-log setup through the Step control cut the local compact stress case to approximately 6 seconds. The prior 180-second WebGL software-renderer timeout remains a failed result, and does not replace standard Chromium CI coverage.
