## Implemented screen

Transport, speed, status, map, person selection, all five command kinds and condition inputs, integer validation, append/delete/up/down ordering, fixed execution-plan inspection, Conflict/clear details, paged scrollable event history, filtering, selection/highlighting, help and stage information use public SDK Canvas UI. HTML supplies metadata and the mount; CSS sizes the mount. Only mount discovery uses the document API. Board input and keyboard actions are owned by the Scene; the independent world model and stage rules are unchanged.

SDK 0.1.3 supplies plain text mirrors, heading levels, stable atomic status/alert regions, raw numeric text keyboard hints, updated focus geometry/reveal, disposal-safe invalidation, clipped draw culling and internal scroll-screen WebGL caching. The game marks its title/section headings, concise playback/target status and validation errors semantically. Per-step logs and counters remain plain text to avoid notification churn. Normal E2E requires label semantics and inputmode attributes rather than opting into candidate-only checks.

No feature remains in an application-managed HTML editor. Pointer drag reordering is deferred: explicit up/down controls support keyboard and touch without conflicting with scroll gestures. Physical Japanese IME, mobile keyboard and screen-reader behavior remain manual validation gaps. Automated native events and semantic attributes are not certification of those devices.

## Code size and interaction tradeoffs

At this checkpoint main.ts grows from 522 to 887 lines, while mount CSS drops from 987 to 17 lines. HTML remains one minified line. These are file line counts, not an assertion that every line change is SDK savings. Canvas owns forms/layout that CSS previously expressed; total main+CSS falls from 1509 to 904 lines. The world-model file has no changes from the HTML baseline. The engine changes reduce native input/accessibility/routing/cache management in application code; they do not guarantee fewer TypeScript lines than native HTML.

The original editor displayed controls in HTML; the Canvas version uses responsive tabs on compact screens and a map/editor split on desktop. Tap targets, real painting after tab changes, list focus, long command/history navigation and editor-driven solutions are verified by the six-project E2E suite. Long history retains all model records and displays at most 80 rows per page. Command rows retain identity on ticks and append; deletion/reorder rebuild affected presentation. Existing integer-step, simultaneous movement, occupancy, rollback, next-step device effects, pathfinding, conditional wait, snapshot and clear behavior remain covered by the unchanged 35 world tests.

## Measured readback cause and final test structure

A retained per-action Chromium 153 trace isolated 32,345ms and 46,178ms inside the pixel-reader evaluate calls, while the complete 2,500ms playback clock advance took about 2,025ms. Browser-compositor capture also incurred roughly 32–36 seconds on large software-WebGL views. Merely copying one pixel or changing capture APIs did not remove the GPU synchronization cost. These measurements identify test readback overhead; they are not a benchmark of player input latency. The earlier broad rendering-cost inference is withdrawn.

The final suite separates 10 functional cases from one dedicated real-pixel regression in each of six projects (66 total). Functional cases keep the normal 60-second budget, including full editor-driven solve and all command/condition validation. The existing 50-command/history stress case retains 180 seconds. The dedicated image case has a 180-second GPU-readback budget and uses the real editor → map → log cache-lease reuse path, verifies the composited selected-tab RGB/alpha, and saves the full viewport. It catches blank paint independently of semantic/model success without adding repeated framebuffer synchronization to every functional helper. Failure screenshots/traces and early error reporting remain enabled.

`pngjs@7.0.0` and `@types/pngjs@6.0.5` are exact MIT-licensed development dependencies for screenshot decoding; production dependencies remain the two registry SDK packages. No runtime framework is added. SDK 0.1.3 semantics plus removal of deferred focus change the Canvas checkpoint main.ts from 894 to 887 lines.

On local Chromium 153, the unchanged full editor solution passed in 20.3 seconds after removing image readback from its functional path; the dedicated image regression passed in 41.4 seconds. A clock-fast-forward experiment did not improve the earlier image-heavy path and is not retained. Standard Chromium final CI remains pending.
