# 世界ステップと実行規則

座標は左上が (0,0)、右が +X、下が +Y。人物と箱は占有物、床・スイッチ・出口は非占有要素。箱の移動命令はない。

## 命令と時間

各人物は同じ整数ステップで最大1回の行動をする。方向移動は1ステップに1マス。目的地移動は開始時に地形だけを見るBFSで経路を確定し、1マスずつ進む。探索順は上・右・下・左。他人物を避ける経路再計算や自動待機はしない。閉じた扉も探索を遮るため、開放を待ってから命令を開始する。

操作は同じマスか上下左右の隣のスイッチに対して1ステップ。待機 N は正の整数 N ステップ。条件待機は開始時の扉状態、人物座標、脱出状態を見る。成立したステップも待機解除に1ステップ使い、次の命令は翌ステップから。同じ座標への目的地移動も1ステップ使う。命令切れの人物はその場に留まり、世界時間は進む。出口に着いた人物はそのステップの確定時に占有を解除する。

## 同時実行と失敗

1. 最後に確定した世界を読み、全人物の行動候補を作る。
2. 値・範囲・通行・同一目的地・開始時占有を検証する。
3. 候補状態へ全行動と命令進行を適用し、出口到達を判定する。
4. 同一ステップの信号を集合として集計し、扉の予約と次ステップ用状態を更新する。
5. 閉鎖予定の扉の占有を検証する。問題がなければ状態とログを一括公開する。

開始時に他人物がいたマスへの進入は禁止。位置交換や、全員が同方向にずれる連鎖移動も禁止。先行者が脱出するステップでも開始時占有を適用する。違反時は**ステップ全体を未確定**とし、座標・命令進行・信号・予約・成功ログのどれも変更しない。失敗を試みたステップ番号のConflict記録だけを履歴の外へ追加する。複数の違反がある場合は人物ID順・検証段階順の最初の原因を表示する。

## 扉と信号

スイッチはパルス信号を送る。同じスイッチへの複数操作もConflictではない。扉は `any`（いずれか）または `all`（全接続先を**同じステップで**操作）の論理で受信する。前ステップ以前の信号はAND条件に持ち越さない。

Step S の受信による開放開始は `S + 1 + delay`、最終開放ステップは `開始 + duration - 1`。重複パルスは開放期限を最大値まで延長する。例えば Step 5、delay=0、duration=3 なら Step 6・7・8 が通行可能、9 から閉鎖。同じステップの通行判定には反映しない。

World の `doors` は「次に試行するステップの開始時に使う状態」。ログの `step` は更新を確定したステップ、`effectiveStep` は設備の効果開始ステップ。Step 8 確定時の閉鎖ログには「Step 9 から閉鎖」と表示する。

閉鎖境界で扉上に人物が残る場合は、その境界を生成したステップ全体をConflictとして取り消す。最後の開放ステップ中に扉から出る移動は可能。扉が人を押し出す・挟む・勝手に開放延長することはない。

## 計画・履歴・描画

再生開始・初期状態からの再実行で、ステージと全命令をdeep copy/freezeする。編集中の計画は実行中・一時停止中のスナップショットに影響しない。`Run` は初期状態、確定計画、乱数シード（現仕様は乱数未使用）、最後の世界、確定ステップ履歴、ログ、Conflictを分離して保持する。逆再生・履歴復元は未実装。

描画は確定した座標間の補間。秒数は再生ペースと表示だけを決め、`advance` の結果に入らない。フレーム欠落で複数ステップを飛ばさず、全ステップを順に処理する。自動再生は200ステップで一時停止する保護がある。必要なら1ステップ操作で継続できる。
